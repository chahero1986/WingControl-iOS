一、这一版解决什么
================================================================
真机反馈：
1. 标准矩阵和 did 全扫描跑完，尾翼都没有任何动作；
2. 测试期间蓝牙断开后，编号仍在推进、指令仍在发送，也没有任何提示。

复查原小程序 onBLEConnectionStateChange：它在断开时会弹「蓝牙已断开」并停止操作。
App 原来有三个缺口：断开事件没转发给测试运行器；排队的写入任务发出前不再检查
连接；标准矩阵默认「无响应写」，而**无响应写没有 ATT 回执**——日志里
「命令已写入」只代表 CoreBluetooth 接受了提交，设备是否收到根本不知道。
所以「两组矩阵全无反馈」有可能是写入在蓝牙层就被拒绝（例如固件要求配对）。

三、请按这个顺序测（很重要）
================================================================
1. 重新 push 编译安装，进「设备 → 一键协议测试」。
2. 连上蓝牙后，**先点「原样复刻小程序 · 一键上升」**（不要先跑矩阵）。
3. 立刻看面板顶部「写入回执」卡片，把那一行字记下来或截图：
   · ATT 写入成功 · 设备已确认      → 蓝牙层送达成功，尾翼不动才是协议/did 问题
   · ATT 写入失败 · code=5 / 15     → 设备要求配对：重启尾翼控制器、
     在「设置 → 蓝牙」忽略该设备后重新连接，配对弹窗要点「允许」；
     再点「读取全部可读特征值（触发配对）」复验
   · ATT 写入失败 · 其它 code       → 把 code 和报告一起发回
   · 失败：设备未连接或特征值不可用 → 重新连接，核对回执卡片里的特征值清单
   · 已提交 · 无响应写（无 ATT 回执）→ 改点「开始标准矩阵」（默认带响应写）
4. 只有在这一帧显示「ATT 写入成功」但尾翼仍不动时，再跑标准矩阵 / did 全扫描。
5. 跑完点「复制测试报告（发给开发者）」粘贴发回；报告现在自带写入统计、
   最后一次回执、写入长度上限、完整特征值清单、断开发生在第几项。

蓝牙断开时：测试会立刻停止、取消所有排队指令，面板顶部弹出橙色提示条；
重新连接后点「继续」可接着跑。未连接时面板直接显示「蓝牙未连接，指令不会发送」。

本机已通过：Swift 静态预检（14 文件 / 71 处 .frame，含新增断线守卫规则）、
协议 24 项校验、build-ipa.sh 语法、全仓 LF + UTF-8、zip CRC 与逐文件 SHA256、
